# 商家资料填写说明

`merchant_profile.json` 是用于验证接口的虚构演示资料，不能作为真实客户信息或经营结论。先复制为另一个 JSON 文件，再将全部演示字段替换成当前客户资料。

## 如何填写

1. 填写商家名称、品类、城市、地址、门店数量、经营阶段、产品及客单价。
2. 记录经营现状、已知问题和经营基线；每条指标注明数值、单位、统计周期、数据来源。
3. 补充门店周边商圈、目标客群、商家希望实现的目标、预算和周期。
4. 填写意向平台、人员/产能/价格等执行约束、效果衡量与复盘安排，以及整体资料来源。

不清楚的信息保持缺失：字符串或数值用 `null` 或省略，列表用 `[]` 或省略。不要用历史案例数据替代当前商家数据。原示例故意缺少地址、商圈和复盘安排，用于展示系统的待补提示。

- 金额使用数值，单位为元；`budget_yuan: 0` 有效。
- 门店数量和周期天数使用正整数，不能写成 `"1"` 或 `"56天"`。
- `baseline_metrics` 每项的 `name`、`value` 必填且为字符串，例如 `"value": "780"`；`period`、`source` 缺失时会提示待补。
- `problems`、`goals`、`platforms` 使用字符串数组。
- 全部输入都标为“用户提供，尚未核验”；填满字段不表示信息已审核。
- JSON 使用 UTF-8（可带 BOM），不要写注释或尾随逗号；字段名和完整限制见项目根目录 `API_USAGE.md` 第 7 节。

## 使用

以下为 CMD 命令。将 `--profile` 后的路径改为你复制并填写的文件：

```cmd
cd /d D:\my_project
.\.venv\Scripts\python.exe -m scripts.generate_proposal "根据商家资料生成营销方案" --profile data\examples\merchant_profile.json --outline-only
```

预览可显示八章中的已填资料和待补字段，不加载模型或访问索引。去掉 `--outline-only`，添加 `--top-k 3`，即可为每章检索最多三条历史参考；添加 `--json` 可查看结构化结果。

API 使用 `POST /agent/chat`，将文件中的对象放入请求的 `merchant_profile` 字段，同时传入 `question`。当前资料按次请求传入，不会自动写入 MySQL 或案例索引；CLI 读取本地文件，API 返回输入与分析准备结果。资料文件和输出均由使用者自行保管。

默认离线模式准备商家输入、缺失项和章节参考。按项目根目录 `DEEPSEEK_SETUP.md` 启用 DeepSeek 后可生成八章正文和建议预算分配；实际报价与业务结论仍需确认，`--outline-only` 始终不调用模型。
