# 历史案例文档

将历史案例的原始 `.pdf` 或 `.pptx` 文件直接放入 `D:\my_project\data\case_documents\`。每份案例可以保留为独立文件，不必合并；建议文件名包含商家、项目和日期，方便识别来源。当前脚本仅扫描此目录的第一层，不递归扫描子目录。旧版 `.ppt` 需先另存为 `.pptx`。

## 与生成模板的关系

生成方案统一采用 `templates/marketing_proposal.md` 中用户确认的八个必需章节：

1. 商家基本情况；
2. 商家现有问题分析；
3. 商家位置与商圈分析；
4. 目标客群分析；
5. 推广目标与预期；
6. 营销策略与活动设计；
7. 执行计划与预算；
8. 效果评估与调整。

历史案例无需按这八个章节重新排版，章节名、顺序和篇幅可以不同。抽取按页或幻灯片进行，不依赖上述八个标题。原始文件应保留，引用使用文件名和页码/幻灯片号。

- 历史案例只有活动策略和效果数据时，可作为这些方面的参考；新商家的位置、商圈和经营基线仍需另行提供。
- 资料缺失标为“待补充”，依据不足的结论标为“待确认”，不补造目标或商家事实。
- 历史案例中的目标、费用和实际结果必须保留其时间、对象、统计口径，不能直接套用到新商家。
- 当前提供 `merchant_profile` 后可按八章分别检索并展示候选原文、当前商家资料和待补项；未提供资料时保留通用模板与集中参考。完整示例见 `data/examples/` 和 `API_USAGE.md` 第 7 节。
- 逐章检索优先排列明确对应的章节标题或已配置别名，但不要求历史文档使用同样标题。其他格式仍可通过语义检索入选；标题差异可能影响排序，需要人工检查候选是否适用。启用 DeepSeek 后可根据资料和候选生成八章分析与建议，配置见项目根目录 `DEEPSEEK_SETUP.md`；原文引用与模拟标记继续保留，生成结果待业务审核。

## 提取范围

PDF 按页抽取，PPTX 按幻灯片抽取。已支持 PDF 可提取的文字，以及 PPTX 普通文本框、嵌套组合对象中的文字、原生表格和带类别缓存的原生图表。表格保留行列关系，图表保留类别、序列和原始数值。扫描件、截图和图片中的文字暂不做 OCR；备注、无类别缓存的图表及复杂排版仍需检查。

## 预览与写入

先预览文件范围及切片数量：

```cmd
cd /d D:\my_project
.\.venv\Scripts\python.exe -m scripts.index_case_documents
```

预览不会写入案例索引。确认文件范围、可提取页数、片段数和 SHA-256，并检查重要内容是否被提取后，再显式写入：

```cmd
.\.venv\Scripts\python.exe -m scripts.index_case_documents --apply
```

文件会写入现有 `.chroma_db` 下独立的 `case_documents` collection，不会混入 `sales_scripts`。当前写入流程会同步本次选中文件的片段，所有导入内容默认标记为待业务审核。明确含“虚构品牌/虚构案例/虚构商家/虚构商户”声明的文件另标记为模拟案例，并在每个检索片段和引用中保留；未命中声明不代表资料真实性已获验证。

首批7份文件、96个片段已获用户确认并写入索引，检索链路已验证。预览快照见 `data/evaluation/case_documents/IMPORT_PREVIEW.md`，写入与验证结果见 `data/evaluation/case_documents/INDEX_RESULT.md`。

项目依赖已声明 `pypdf` 和 `python-pptx`，缺失时先按项目依赖配置安装。
